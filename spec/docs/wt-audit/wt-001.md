# WT-001 — IsolationStateChange drops `base_commit`

## Problem

When an isolated session is created, the `IsolationStateChange` stream chunk emitted to all
TUI clients carries `base_commit: None`, even though the manager has the SHA in hand at that
exact moment. The TUI therefore can never render the worktree's base commit in the isolation
badge / branch indicator, and any client-side logic that wants to know "what was this
worktree forked from?" has to make a second round-trip it has no reason to make.

## Evidence

**Wire type (has the field, since RPC-036)** — `rust/rpc-types/src/lib.rs:1462`:

```rust
IsolationStateChange {
    is_isolated: bool,
    worktree_path: Option<String>,
    base_commit: Option<String>,
}
```

**Both constructors exist** — `rust/rpc-types/src/lib.rs:1691` and `:1703`:

```rust
/// GIT-029 / RPC-036: pre-RPC-036 callers using the 2-arg form get `base_commit = None`.
pub fn isolation_state_change(is_isolated: bool, worktree_path: Option<String>) -> Self

/// RPC-036: … Use this constructor when emitting from a code path that
/// has the baseline SHA in hand (e.g. `SessionManager::create_isolated_session`).
pub fn isolation_state_change_with_base(
    is_isolated: bool,
    worktree_path: Option<String>,
    base_commit: Option<String>,
) -> Self
```

**The creation path uses the 2-arg form** — `rust/sessions/src/session_manager.rs:1183`
inside `create_isolated_session_with_id` (GIT-028):

```rust
// RPC-041: Emit IsolationStateChange directly on the manager-owned chunks_tx
let _ = self.chunks_tx.send((
    codelet_rpc_types::SessionId::from(id.to_string()),
    codelet_rpc_types::StreamChunk::isolation_state_change(   // ← 2-arg, base_commit: None
        true,
        Some(worktree_path.to_string_lossy().to_string()),
    ),
));
```

`base_commit` is a local variable in the same function (`:939`) and is returned in the
`IsolatedSessionInfo` result (`:1199`) — it is only not threaded into the chunk.

`isolation_state_change_with_base` has **zero production call sites** (grep across `rust/`
shows only its definition + rpc-types unit tests).

**Downstream consumers of the field:**
- `rust/fspec-tui/src/app/dispatch_stream_chunks.rs:80` — folds the chunk into
  `AgentViewStore::set_isolation_state` with `base_commit` as-is.
- `rust/fspec-tui/src/store/agent_view/isolation_state.rs:34` — `IsolationState { is_isolated,
  worktree_path, base_commit }` read by the SessionHeader isolation badge.

## Impact

- TUI isolation badge never shows the base commit (the struct field exists, always `None`).
- Any future UX ("merge from base X", "show N commits behind main") is blocked at the wire.
- The wire contract for RPC-036 is dead on arrival for the only production emitter.

## Proposed fix

One-line change at `session_manager.rs:1183` — switch to
`StreamChunk::isolation_state_change_with_base(true, Some(path), Some(base_commit.clone()))`.
Add/extend a source-shape test (the pattern pinned in
`rust/sessions/tests/session_manager_shape.rs:449`) asserting the 3-arg constructor is used
in `create_isolated_session_with_id`, mirroring how RPC-041 pinned the direct `chunks_tx.send`.
