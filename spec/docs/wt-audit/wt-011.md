# WT-011 — Worktree plumbing hardcodes `<repo>/.git` layout; `codelet_git::IsolatedSessionInfo` is dead production code

## Problem

### (a) `list_worktrees` reads HEAD from a hardcoded path

`rust/git/src/worktree.rs:197-202`:

```rust
let head_path = repo_path
    .join(".git/worktrees")
    .join(&session_id)
    .join("HEAD");
```

while `create_worktree_at_ref` and `remove_worktree` in the same file compute the path
correctly via `repo.git_dir()` (`:101-102`, `:141-142`). For any repository whose git
directory is not literally `<repo_path>/.git` — linked worktrees, submodules,
`GIT_DIR`/`core.worktree` layouts, or fspec's own repo when fspec is run from a
**submodule checkout** — `list_worktrees` either:

- reads a nonexistent HEAD → reports `head_commit: "unknown"`, `is_detached: true`
  (`read_worktree_head` `:308-311`), which then propagates into
  `SessionInfo.base_commit` (`session_status.rs:403`) and into
  `list_session_worktrees`'s `head_commit`/`base_commit` fallback
  (`handle_impl.rs:2017-2024`), or
- silently omits entries it cannot read (well — it still lists the dir entry, but with
  garbage HEAD data).

### (b) `commindir` is hardcoded to `../..`

`worktree.rs:298`:

```rust
fs::write(worktree_git_dir.join("commindir"), "../..\n")?;
```

This is only correct when `worktree_git_dir == <repo>/.git/worktrees/<sid>` (two levels
below the common dir). If the main repo's git dir is elsewhere (see (a)), the commindir
file is wrong and **git/gix will mis-resolve the common objects/config for the
worktree** — checkout, status, and every gix operation in the worktree can break or
read the wrong objects. The value should be computed as the relative path from
`worktree_git_dir` back to `repo.git_dir()`.

(The same class: `session_result.rs` and `tree_utils.rs` open the worktree repo via
`open_repo(worktree_path)` — `gix::open` on the worktree dir — which works *because* the
gitfile+commindir are right for the standard layout; it is the one consumer that would
notice a broken commindir, but only with an opaque error.)

### (c) `codelet_git::IsolatedSessionInfo` is dead production code

`rust/git/src/isolated_session.rs` (GIT-019) — `IsolatedSessionInfo` with
`new_isolated` / `new_isolated_at_ref` / `new_non_isolated` / `effective_cwd` /
`is_isolated` — is re-exported from `rust/git/src/lib.rs:34` but has **zero production
call sites**:

```
grep 'IsolatedSessionInfo::new_isolated|::new_non_isolated' rust/
  → only rust/git/tests/* and rust/napi/tests/isolated_session_creation_test.rs
```

`SessionManager::create_isolated_session_with_id` (the only isolated-creation path)
calls `codelet_git::create_worktree` directly (`session_manager.rs:935`) and constructs
the **wire** `codelet_rpc_types::IsolatedSessionInfo` itself (`:1199`). So the git crate
ships a parallel "isolation info" type that nothing in the product uses — a maintenance
trap (two types, same name, different fields: `PathBuf` vs `String`) and dead weight.

## Impact

- (a)+(b): latent breakage for any non-standard git-dir layout; fspec's own repo is a
  realistic trigger (submodule/linked-checkout development flows).
- (c): divergence risk — future GIT cards may "fix" `IsolatedSessionInfo` thinking it
  is live, or build on it, while the real path uses `WorktreeCreateResult`.

## Proposed fix

1. `list_worktrees`: use `repo.git_dir().join("worktrees")` like the sibling functions.
2. `write_worktree_metadata`: compute `commindir` as the relative path
   `repo.git_dir()` → `worktree_git_dir` (git itself does exactly this in
   `git worktree add`; a `pathdiff`/manual `..` count works), and test with a repo whose
   git dir lives outside the workdir (create one in the test with `gix::init` into a
   separate dir + gitfile).
3. Either delete `isolated_session.rs` (and its tests, folding their value into
   `worktree.rs` tests) or make `create_isolated_session_with_id` consume it
   (`IsolatedSessionInfo::new_isolated(project, id)` → map to the wire type), so there is
   one isolation-info type on the git side.
