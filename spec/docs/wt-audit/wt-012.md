# WT-012 — `create_isolated_session_with_id` duplicates the pre-RPC-425 session bootstrap instead of using the shared helper

## Problem

RPC-425 extracted the shared session-creation logic out of `create_session_with_id` and
`create_session_from_manifest` into
`rust/sessions/src/session_creation_helper.rs` (`create_background_session_inner` +
`SessionCreationParams`), explicitly to prevent the two paths from drifting. The
isolated-creation path was **never migrated**:
`SessionManager::create_isolated_session_with_id`
(`rust/sessions/src/session_manager.rs:916-1204`, ~290 lines) re-implements every step
inline.

Side-by-side (isolated path → shared-helper equivalent):

| Step (inline in isolated path) | Shared-helper equivalent |
| --- | --- |
| `parse_model_string` + registry/codex/profile branching (`:953-1026`) | `parse_model_string` at caller + `apply_model_selection` (`session_creation_helper.rs:167`) |
| `ProviderManager::with_provider_and_model` / `with_model_support` branches (`:1000-1026`) | caller builds PM, helper applies selection |
| `set_session_model_vision` + `set_session_model_max_images` (`:1033-1044`) | `:171-182` |
| `Session::from_provider_manager` + profile `preserve_thinking` seeding | helper does NOT cover this (isolated path has NO preserve-thinking seeding — a real drift already present: profile models in isolated sessions silently miss the PROV-143 seed) |
| `inject_context_reminders_with_isolation` (`:1059`) | `:216-220` (helper takes an `isolation` param for exactly this) |
| `load_lifecycle_hooks` (`:1061-1072`) | `:222-233` |
| `BackgroundSession::new(…)` (`:1074-1087`) | `:235-248` |
| `set_owning_manager` (`:1092`) | done by the caller in the other paths (`:703`, `:867`) |
| thinking-level seeding (`:1097-1103`) | `:251-257` |
| model limits + compaction threshold (`:1105-1121`) | `:295-306` |
| pre-tool hook registration block (`:1123-1159`) — byte-identical to `:308-343` in the helper | `:308-343` |
| `init_mcp_session` (`:1161`) | `:345` |
| `spawn_agent_loop` (`:1163`) | caller |

## Drift already present (evidence the failure mode is real)

1. **PROV-143 (preserve-thinking seed)**: `create_background_session_inner` seeds
   `inner.preserve_thinking_enabled` from the profile for profile models
   (`session_creation_helper.rs:195-213`). The isolated path never does — a profile-model
   isolated session keeps the historical preserve behavior, contradicting the profile's
   stored default.
2. **PROV-142 (auto-continue seed)**: the helper seeds `set_continue_state` from the
   profile (`:264-288`). The isolated path never does — isolated sessions always start
   with the `BackgroundSession::new` default budget.
3. **`set_default_model` asymmetry**: `create_session_with_id` calls
   `self.set_default_model(model)` (`session_manager.rs:733`); the isolated path does not.
4. **IsolationStateChange emission**: only the isolated path emits it (`:1183`), and it
   drops `base_commit` (WT-001); if the helper absorbed the path, the chunk emission
   would need to move into the helper's post-creation contract.

## Impact

- Every future session-bootstrap change (PROV-*, HOOK-*, RPC-* — the comments in the
  helper are dense with them) must be applied to two places or the isolated path
  silently regresses. Two concrete regressions already exist (items 1–2 above).
- The file is ~1,300 lines; the 300-LoC ceiling (CLAUDE.md) is already exceeded for
  this function's contribution, and the duplication makes it harder to shrink.

## Proposed fix

Migrate `create_isolated_session_with_id` onto `create_background_session_inner`:

1. It already has everything the helper needs: `uuid`, `name`, `project`,
   `project_path`, `ParsedModelInfo`, `provider_id`, `model_id`, plus
   `worktree_path`, `base_commit`, `isolation` (the `Option<IsolationContext>` field on
   `SessionCreationParams` exists **precisely for this** and is today only ever `None`).
2. Keep in the manager method: the worktree creation + git-manifest write
   (`create_worktree`, `create_session_manifest` — isolation-specific, stay), the
   `IsolationStateChange` emission (fix per WT-001), and the footer-poller call with the
   worktree cwd.
3. Fix `SessionCreationParams`'s model: the helper currently takes a pre-built
   `ProviderManager`, but the isolated path needs the profile/codex
   `with_provider_and_model` branches — either move that selection into a shared
   `resolve_provider_manager` helper, or pass a small `ProviderSelection` enum into the
   shared helper (the two existing callers already share 90% of this code).
4. Add the missing PROV-143 / PROV-142 seeds (they come for free once the path is
   shared), and add source-shape tests (pattern:
   `rust/sessions/tests/session_manager_shape.rs:581` which pins the signature) asserting
   the isolated path calls `create_background_session_inner`.
