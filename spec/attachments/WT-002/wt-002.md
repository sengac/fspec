# WT-002 — Footer poller never runs in the `fspec` binary

## Problem

The per-session footer poller — a 5-second background task that reads the session's
effective CWD from the footer-cwd registry, polls `get_current_branch`, and emits
`StreamChunk::FooterStateUpdate` — is implemented **only** in the NAPI adapter
(`rust/napi/src/footer_poller.rs`, installed via `install_napi_session_manager_hooks`
called from `session_set_global_chunk_callback` in `rust/napi/src/session_bindings.rs:1478`).

The Rust binary (`fspec combined` / daemon, the primary frontend) installs
`FspecAgentHooks` in `rust/fspec/src/common.rs:135`:

```rust
manager.set_hooks(Arc::new(FspecAgentHooks::new()));
```

and `FspecAgentHooks::spawn_footer_poller` (`rust/agent-loop/src/hooks.rs:78`) is a
documented no-op:

```rust
fn spawn_footer_poller(
    &self,
    _session_id: String,
    _cwd: String,
    _worktree_path: Option<String>,
) {
    // Footer poller stays NAPI-only for now (TUI-091).
}
```

Both `create_session_with_id` (`session_manager.rs:900`) and
`create_isolated_session_with_id` (`:1191`) call
`self.hooks().spawn_footer_poller(...)`, so in the binary the call is a silent no-op.

## Impact

In the `fspec` binary:

- The SessionFooter's CWD/branch line is never updated by the poller; it only ever changes
  if the Bash tool happens to run (the footer-cwd registry is otherwise only written by
  `BashTool::resolve_and_track_cwd`, `rust/tools/src/bash.rs:91`).
- For **isolated sessions this matters most**: fspec worktrees are created in a
  **detached HEAD** state (`worktree.rs:122` `is_detached: true`, HEAD file contains a bare
  SHA — verified live with the git CLI: `git status` in a created worktree prints
  `## HEAD (no branch)`). So the footer can show *nothing* branch-like for the session's
  whole lifetime, with no "(detached)" indication, even though the isolation badge shows
  ACTIVE.
- The footer poller was the intended mechanism for the TUI to learn the worktree's git
  state without per-frame polling; its absence means the RPC-045 `FooterStateUpdate`
  stream simply never fires in the embedded transport.

## Affected code paths

| File | Role |
| --- | --- |
| `rust/napi/src/footer_poller.rs` | The only real implementation (`spawn_footer_poller`, `stop_footer_poller`, `FOOTER_POLLER_TOKENS`) |
| `rust/napi/src/session_hooks.rs:44` | NAPI hooks impl delegating to the above |
| `rust/agent-loop/src/hooks.rs:78` | `FspecAgentHooks` — no-op impl used by the binary |
| `rust/sessions/src/session_manager.rs:99,126` | `SessionManagerHooks` trait + default no-op |
| `rust/fspec/src/common.rs:135` | Where the binary installs `FspecAgentHooks` |
| `rust/fspec-tui/src/app/dispatch_stream_chunks.rs:98` | TUI consumer of `FooterStateUpdate` (dead input in the binary) |

## Proposed fix

Move the poller out of the NAPI crate into a NAPI-free location (e.g. `codelet-agent-loop`
next to `FspecAgentHooks`, or `codelet-sessions`) so both hook impls share it. It needs:
- session id + initial cwd + worktree_path (already in the trait signature),
- the `chunks_tx` broadcast (obtainable via `SessionManager::instance().chunks_tx()` or by
  passing the manager),
- `codelet_tools::footer_cwd` (already NAPI-free) and `codelet_git::get_current_branch`
  (already NAPI-free).

Then have `FspecAgentHooks::spawn_footer_poller` call it, and keep the NAPI path
delegating to the same helper (no behavior drift — see the "two front doors" rule in
CLAUDE.md). Add a scenario to a feature file under `spec/features/` (footer poller parity
across hook impls) with tests asserting `FooterStateUpdate` chunks are emitted from a
session created under `FspecAgentHooks`.

## Notes / verification

- Confirmed `spawn_footer_poller` has exactly two non-trait implementations (napi +
  no-op default) and one real body (napi footer_poller.rs) by grep across `rust/`.
- `get_current_branch` uses `gix::discover` (walks up), so pointing it at a worktree path
  works; it returns `None` for detached HEAD (status.rs:183) — the poller should surface a
  "detached" marker instead of an empty branch string so the badge and footer agree.
- The TUI-091 comment in `footer_poller.rs` explicitly documents the "do NOT poll
  staged/unstaged" optimization — keep that when moving it.
