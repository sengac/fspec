## 7. build_shutdown_future signature (CHANGES — Slice 3)

**Location:** `codelet/fspec/src/common.rs:201` and `:216`

Current: `pub fn build_shutdown_future() -> impl Future<Output =
Result<()>>` — races SIGINT OR SIGTERM, yields `Ok(())`.

**Note:** AstGrep returned TWO matches because the file appears to have
both a unix and a non-unix cfg-gated definition (line 201 is unix path;
line 216 is the windows-or-fallback path).

**RPC-011 change (architecture note [5]):**
```rust
pub enum ShutdownReason { Sigint, Sigterm, Sighup }
pub fn build_shutdown_future() -> impl Future<Output = Result<ShutdownReason>>
```

`daemon.rs` gains a TOP-LEVEL loop: `loop { match shutdown.await { Sighup
=> rebuild_watcher_and_continue, Sigint|Sigterm => drain_and_break }}`.
`combined.rs` and `client.rs` treat any signal as exit (no SIGHUP
handling in TUI modes).

1. The new `request_shutdown(stats: &ServerStats)` fn (architecture

3. The daemon awaits the existing `JoinHandle` for up to 5 seconds
   before falling back to `handle.abort()`.

## 10. WebSocketFspecBackend (additive — Slice 1/2)

**Location:** `codelet/fspec-tui/src/transport/websocket.rs:43`

Current: `pub async fn connect(url: url::Url) -> Result<Self>` returns
a `WebSocketFspecBackend { client: FspecWsClient }` with no auto-reconnect.

**RPC-011 additions (rule [21], architecture note [0]):**
1. The struct grows `Arc<RwLock<Option<FspecWsClient>>>` and an
   `UnboundedSender<Action>` field.
2. A SECOND constructor:
   ```rust
   pub async fn connect_with_supervisor(
       url: url::Url,
       action_tx: UnboundedSender<Action>,
   ) -> Result<Self>
   ```
   spawns a tokio supervisor task wrapping `tokio_tungstenite::connect_async`
   in an exponential-backoff loop (250 → 500 → 1000 → 2000 → 5000 cap).
   On successful frame the supervisor stores the new client and emits
   `Action::Reconnected`; on disconnect detect it stores `None` and
   emits `Action::Disconnected`; on every retry attempt before sleep it
   emits `Action::Reconnecting(attempt)`.
3. All trait method bodies grab a read-lock and delegate; if the slot
   is `None` they return `Err(BackendError::Disconnected)`.
4. The existing `connect(url)` signature is preserved (rule [16]
   regression) — it stays as a no-supervisor convenience for tests.

## 11. New `DisconnectDialog` component (new — Slice 1)

**Location:** `codelet/fspec-tui/src/components/disconnect_dialog.rs`
(NEW FILE, alongside `help_dialog.rs`).

Follows the `HelpDialog` shape (lines 1-114 of help_dialog.rs):
- `priority() -> Priority::Critical`
- Body is `tui_popup::Popup` with a `SizedWidgetRef` adapter (NO new
  framework, NO hand-rolled `centered_rect`).
- ESC is NOT a keybinding (the dialog only honours `q` and `r`).
- Mutable state: `attempt: Option<u32>` so the body text can toggle
  between `"daemon disconnected"` and `"auto-reconnecting (attempt
  N)…"`. `App::dispatch` updates this on `Action::Reconnecting(n)`.

App-level integration (architecture note [1]):
- `App::dispatch` matches `Action::Disconnected` → push DisconnectDialog
  with `attempt = None`; `Action::Reconnecting(n)` → mutate the topmost
  DisconnectDialog's attempt to `Some(n)`; `Action::Reconnected` →
  remove DisconnectDialog from the compositor (by id).
- When DisconnectDialog is topmost (Critical), App's `handle_event`
  short-circuit at line 336-363 already swallows `?`/`q` etc. — we add
  a check inside the dialog's own `handle_event` to allow ONLY `q`
  (→ `should_quit = true`) and `r` (→ `Action::ManualReconnect` or
  similar — TBD during TESTING).

## 12. New `fspec status` subcommand (new — Slice 6)

**Location:** `codelet/fspec/src/status.rs` (NEW FILE, ~80 lines per
architecture note [7], alongside `client.rs` and `daemon.rs`).

`main.rs::Mode` enum gains `Status { connect: Option<String> }` next to
`Daemon` and `Client`. `status::run` opens a one-shot
`WebSocketFspecBackend::connect` (no supervisor), calls `backend.health()`,
pretty-prints, exits 0; on any failure writes one stderr line and exits 1.

Failure modes covered (scenarios 21-23):
1. `no daemon.json found` → stderr "fspec daemon: not running (no
   daemon.json at <path>)", exit 1.
2. Stale `daemon.json` → `read_and_verify_daemon_json` deletes the
   file → stderr "fspec daemon: not running (stale daemon.json
   removed)", exit 1.
3. `--connect <url>` override bypasses autodiscovery entirely.
