# WT-006 — Session merge/diff machinery is git-blind: ignore rules, symlinks, modes, and modify/delete conflicts

## Problem

`codelet-git`'s session diff/merge operates on **raw directory scans** rather than git
state, which produces a cluster of related correctness defects:

### (a) Gitignored files are invisible to the session diff

`collect_worktree_files` (`rust/git/src/tree_utils.rs:37-119`) collects:
- tracked files (index entries whose file exists on disk), and
- untracked files **that are NOT ignored** (via `repo.excludes(...)` at `:71-75`).

Consequences:

1. `get_session_diff` / `inspect_session_changes` (the `/merge-worktree` pre-flight) can
   report **zero changes while the worktree is full of build artifacts** the user (or the
   agent) produced — `target/`, `node_modules/`, logs. The dialog says "nothing to merge"
   and the user assumes no work was done.
2. Worse, `apply_session_changes`'s re-merge path uses `collect_worktree_files` for
   **both** the worktree and the main workdir. The deletion sweep in
   `apply_worktree_to_main` (`session_result.rs:330-338`) removes from main any base file
   the worktree "lost" — but gitignored files in MAIN that were created after session
   start are invisible to the worktree-side scan and are never in scope, while gitignored
   files that existed in the worktree at base (e.g. a committed-but-ignored… no —
   specifically: files matching ignore patterns present in the base tree are tracked and
   *are* scanned). The realistic corruption: **a file that is ignored in the worktree but
   was tracked at base** (e.g. someone adds a pattern mid-session) disappears from the
   worktree scan → treated as deleted → deleted from main on merge.

### (b) Symlinks cannot round-trip

- `collect_tree_files_recursive` (`tree_utils.rs:192-195`):
  `_ => { /* Skip symlinks and submodules for simplicity */ }` — symlink tree entries are
  dropped from every base-tree read.
- `checkout_to_worktree` (`rust/git/src/checkout.rs:81-83`): `EntryKind::Link =>
  checkout_symlink(...)` is implemented, but `get_tree_files` drops them, so any
  diff/apply/merge computation treats symlink files as absent → the apply path will
  **delete the symlink target file from main** (main had it, "worktree" doesn't → deleted
  list) instead of preserving it.
- Submodules (`EntryKind::Commit`) are skipped in checkout entirely (`checkout.rs:84-86`):
  an isolated session of a repo with submodules has empty submodule dirs, and a merge
  back cannot restore them.

### (c) File modes are flattened

`build_tree_from_index` (`rust/git/src/repo_ops.rs:232-244`) only tracks
`mode == Mode::FILE_EXECUTABLE` — the executable bit. Git's mode set (100644 / 100755 /
120000 symlink / 160000 gitlink) is otherwise lost. `build_tree_from_files`
(`ghost_commit.rs:194`) does the same. So a ghost-checkpoint or `git_commit` of a
worktree with a 0o444 file records it as 0o644.

### (d) `git_add` / `git_commit` in the worktree are root-repo-only

`git_add`/`git_commit` (`repo_ops.rs`) hardcode `path.join(".git/index")` and
`path.join(".git/HEAD")` — inside an fspec worktree the git data lives in
`<repo>/.git/worktrees/<sid>/`, so these helpers **cannot operate on a worktree at all**
(the `.git` in the worktree is a *file*, not a dir). Anything that calls them expecting
worktree semantics (the LLM told it can commit in the worktree) fails or, worse, touches
the main repo's index if `dir` is the main repo root.

## Impact

- "/merge-worktree doesn't work" reports for repos with symlinks or submodules
  (silently drops/deletes the symlinked content).
- "nothing to merge" false negatives for artifact-producing sessions.
- Mode-bit drift after checkpoints; `git_commit` unusable inside worktrees.

## Proposed fix

1. Make `get_tree_files` / `collect_worktree_files` return a richer entry type
   (content + mode + kind: blob/symlink/gitlink) and carry that through
   `detect_conflicts` / `apply_worktree_to_main` (preserve symlink targets; treat
   gitlinks as atomic).
2. For the diff/inspect path, prefer a **git-aware diff** (`gix::diff` between the base
   commit and the worktree index+workdir) over the byte-map scan — this fixes the
   ignore-rule, mode, and symlink cases at once and is much faster than scanning.
3. Route `git_add`/`git_commit` through `open_repo(dir)` + `repo.index()`/
   `repo.head_ref()` (as `ghost_commit.rs` already does) instead of hardcoded
   `.git/index` joins, so they work identically in main and linked worktrees.

## Tests

- Repo with a symlink (committed) → create worktree → diff → merge → symlink survives.
- Repo with a submodule → same.
- 0o444 file → checkpoint → mode preserved.
- Build artifacts in worktree → inspect reports them as (ignored) or the UI distinguishes
  ignored-from-tracked so "nothing to merge" is honest.
