# AST Research: SessionModel and NAPI Session State Pipeline

## Rust SessionModel (codelet/napi/src/session_manager.rs:396–401)

```rust
#[napi(object)]
#[derive(Clone)]
pub struct SessionModel {
    pub provider_id: Option<String>,
    pub model_id: Option<String>,
}
```

**Only 2 fields.** No context_window or max_output_tokens. This is the struct that needs to be extended.

`session_get_model()` (session_manager.rs:6693) constructs `SessionModel` from the session's `provider_id` and `model_id` RwLocks.

## Data Flow

```
Rust SessionStateChange event
  → refreshSessionState(id) → version++ → notify subscribers
  → useSyncExternalStore → getSessionSnapshot()
  → calls sessionGetModel() → returns SessionModel { provider_id, model_id }
  → TUI uses rustSnapshot.model.modelId → findModelInProviders(providerSections)
  → reads contextWindow from models.dev NapiModelInfo
```

## Required Changes

1. **Rust `SessionModel`**: Add `context_window: Option<u32>`, `max_output_tokens: Option<u32>`
2. **`session_get_model()`**: Populate from `session.provider_manager().context_window()` and `.max_output_tokens()`
3. **TUI `SessionModel` type**: Auto-generated by NAPI from Rust struct
4. **`AgentView.tsx` `rustModelInfo` useMemo**: Use `rustSnapshot.model?.contextWindow` when available, fallback to providerSections lookup
5. **`snapshotsAreEqual()`**: Ensure SessionModel equality check covers new fields
