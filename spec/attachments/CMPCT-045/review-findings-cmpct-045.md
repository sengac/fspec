## 🟡 Warnings (Should Fix)
1. **Custom-provider compactor sub-agent escapes the 7-tool read-only surface (Rule [6]/[11], CMPCT-044 Rule [3])** — `rust/agent-loop/src/generate_compaction_handler.rs:189-216`: when `custom_provider_registered(provider_name)` is true, the ephemeral sub-agent is built via `CustomProvider::create_rig_agent(...)`, whose tool chain (`rust/providers/src/custom/custom_provider.rs:266-303`) attaches the FULL provider surface to the sub-agent — including `GenerateCompactionTool` (lines 272 and 297) and `InjectSummaryTool` (lines 270 and 295), plus `DeepSearchTool`, `AgentManagerTool`, `ScheduleTool`, `ConnectMcpTool`, `GraphSearchTool`, `Fspec`, `Bridge`. This breaks the "exactly 7 read-only tools, no recursion into compaction, no inject_summary" contract (Rule [5]/[6]: "no inject_summary, no Write/Edit"; Rule [11]: "The ephemeral compactor sub-agent's 7-tool surface does NOT include GenerateCompaction (no recursion into compaction)"). A custom-provider compactor sub-agent could itself invoke `GenerateCompaction` (the handler registry is populated per-session for every turn at `rust/agent-loop/src/agent_loop.rs:765-771`) or call `inject_summary` (the pin is supposed to be handler-side only). The compile-time `SUB_AGENT_TOOL_COUNT == 7` assert at `generate_compaction_handler.rs:176-179` guards only the native-provider macro path, and the tool-surface tests (behavioral file lines 1434-1470) only assert on `SUB_AGENT_TOOL_NAMES` constants — nothing catches this. DeepSearch's `build_and_run_agent` (rust/agent-loop/src/deep_search_handler.rs) has the same shape; fix both or explicitly document the exception.
2. **Pin-mutation duplication vs CMPCT-044 (DRY)** — `rust/agent-loop/src/generate_compaction_handler.rs:587-597` (cross-session pin: `reset_session_to_reminders(&mut inner)` → push `wrap_dag_content(&dag_text)` as User message → `recalculate_token_tracker(&mut inner)` → `inner.token_tracker.reset_after_compaction()`) is a verbatim re-implementation of `codelet_cli::compactor_sub_agent::pin_dag_to_session` (`rust/cli/src/compactor_sub_agent.rs:115-131`), which the design doc (`spec/attachments/CMPCT-045/CMPCT-045-generate-compaction-design.md:116`) explicitly says to reuse ("Pin primitive callable with a DAG string (handler-side) — reuse `apply_pending_dag` body / `force_inject_fallback_dag`"). The CLI crate already exposes this exact primitive. Call `pin_dag_to_session(&mut inner, &dag_text)` and keep only the flag-clear + emit divergence.
3. **Fallback-DAG assembly triplicated** — the partial-node-recovery + generic-D1-node assembly now exists in three places: (a) `rust/agent-loop/src/generate_compaction_handler.rs:649-664` (`build_fallback_dag`, label "Auto-recovered: compaction timeout"); (b) `rust/agent-loop/src/agent_loop.rs:1469-1492` (watchdog Level-3, label "Auto-recovered: compaction timeout", message "convergence timeout"); (c) `rust/cli/src/compactor_sub_agent.rs:240-249` (`pin_fallback_dag`, label "Auto-recovered: context overflow"). The shape is stable (CMPCT-020 Level-3) — a single shared `build_recovered_or_generic_dag(text, label, turns)` in `codelet_cli::compaction_dag` (which already owns `extract_partial_dag_nodes_from_text`, lines 231-236) would prevent the labels/messages from drifting.
4. **File size over the ~300-line guideline** — `rust/agent-loop/src/generate_compaction_handler.rs` is 739 lines (≈435 production lines: `execute_compaction_subagent` spawner :71-152, `build_and_run_compactor_agent` :163-326, `register_compactor_sub_agent_handler` :339-379, `register_generate_compaction_handler` :409-449, `execute_generate_compaction` :457-632, `with_fallback_note` :637-644, `build_fallback_dag` :649-664) and `rust/cli/src/compaction_dag.rs` is 450 lines (≈358 production: ~130 lines of instruction constants :34-129, detection :146-164, extraction :171-236, force-inject :253-277, prompt builder :301-356). Justification: the handler file mixes two work units' concerns (CMPCT-044 spawner + CMPCT-045 tool handler) — the natural split is `compactor_spawner.rs` (spawner + registration) vs `generate_compaction.rs` (tool handler + dispatcher); `compaction_dag.rs` is mostly constant strings + focused functions. Neither blocks, but split on next touch rather than grow further.
5. **Lifecycle step "progress update before spawn" is not asserted in tests** — Scenario "Compaction lifecycle events are emitted on the target session" (feature line 219) step *"Then the target emitted a Compacting state change and a compaction progress update before the sub-agent was spawned"*: the behavioral test `compaction_lifecycle_events_carry_the_recalculated_post_pin_basis` (`rust/agent-loop/tests/cmpct045_generate_compaction_behavioral.rs:1046-1068`) asserts only the Compacting/Running `SessionStateChange` ordering and the `CompactionComplete` chunk. The implementation does emit the progress update (`generate_compaction_handler.rs:510-514`, `update_compaction_progress("Compaction sub-agent working", 0, total_turns)`), but no `@step`-anchored assertion checks for the `CompactionProgress` chunk in the target's buffered output — the step is covered by implementation, not by a real assertion.

## 🟢 Observations (Nice to Have)
1. `rust/agent-loop/tests/cmpct045_generate_compaction_behavioral.rs` (1531 lines) is a single monolithic file containing all 20 test functions, but it is organized by concern (section banners, shared fixture block at top lines 42-358, process-global serial guard line 47, `#[serial]` on registry tests) and the 1:1 test-file convention is upheld. Could be split into `*_prompt.rs` / `*_pin.rs` / `*_registry.rs` for easier bisection; acceptable as-is.
2. The tool-surface test exists twice: `cmpct045_generate_compaction_behavioral.rs:1434-1470` (`compactor_sub_agent_has_only_the_read_only_tool_surface`) and the inline `#[cfg(test)]` in `generate_compaction_handler.rs:674-705` (`compactor_sub_agent_keeps_the_seven_read_only_tools`) — identical assertions on `SUB_AGENT_TOOL_COUNT`/`SUB_AGENT_TOOL_NAMES`. The feature's 1:1 rule says every scenario's steps live in the one test file; keep only the behavioral copy (or vice versa), not both.
3. `with_fallback_note` (`generate_compaction_handler.rs:637-644`) prepends `[free force-inject fallback — …]` to the tool RESULT only, not to the pinned message — correct per Rule [13] (the pinned message stays clean). A future reader of a pinned fallback DAG gets no in-context marker that it is a coarse auto-recovery; the generic node's label "Auto-recovered: compaction timeout" is the only marker. Stylistic only.
4. `rust/tools/src/generate_compaction/mod.rs:196` — `serde_json::to_value(&args).unwrap_or_default()` silently substitutes an empty value for pre-tool-hook payloads on serialization failure; a `tracing::debug!` on the failure arm would aid debugging hook behavior. (Matches the DeepSearch clone exactly, so this is inherited, not new.)
5. Scenario "Successful sub-agent DAG is pinned to the target session" step *"And the persisted session manifest history is NOT truncated"* (feature line 143) is verified by a comment only (`cmpct045_generate_compaction_behavioral.rs:466-468`), not an assertion. Sound — the pin provably never touches persistence (the unknown-target test asserts zero side effects, lines 714-741) — but an explicit manifest-length check would make the step airtight.
